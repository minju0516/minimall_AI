## 3. 가정 (계약서에 없는 부분을 어떻게 해석했는가)
- 교수님 안내에 따라 2인 팀으로 진행하며, 미션마다 두 사람이 번갈아 역할을 맡는다. 한 사람이 드라이버를 하면 다른 사람이 내비게이터와 검증자를 겸하고 기록도 맡는다.
- Mission 5(orderQuery.js 코드 리뷰)는 필수 미션이므로 M4 이후에 진행한다. 계획표 2번은 양식대로 M1~M4만 적고, M5는 REVIEW_NOTES.md에 기록한다.
- 도전 과제(expiry.js)도 진행했다.
- addToCart 에서 합산 수량이 99를 넘어도 재고 이내이면 허용한다. 1~99 검사는 인자 quantity 에만 적용한다. (계약서에 명시 없음)
- getCart 는 STOPPED 상품도 그대로 표시한다.
- changeQuantity 의 maxAddable 은 재고 기준 max(0, stock) 이다.
- removeItem 은 판매 상태와 무관하게 장바구니에 있으면 삭제한다.

## 4. 안전장치 (우리 팀이 지킬 것 4가지)
1. 한 번에 함수 하나 또는 수락 기준 하나만 작업하고, `docs/SRS_발췌.md`와 `docs/API_CONTRACT.md`를 대조한다.
2. 공개 테스트와 공통 도구 파일은 수정하지 않으며, 해당 미션 테스트 결과와 diff를 검증자가 확인한 뒤 수락한다.
3. 키·토큰·개인정보·카드번호를 코드, 테스트, 로그, 대화에 기록하지 않는다.
4. 같은 시도가 3번 실패하면 멈추고, 원인 가설을 세운 뒤 계획부터 다시 받는다.
