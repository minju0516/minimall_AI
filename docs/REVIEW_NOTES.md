## 리뷰 체크리스트 (확인한 항목에 표시)
- [O] 명세 일치: 수락 기준을 모두 만족하는가? 요구하지 않은 동작은 없는가?
- [O] 보안 · 권한: 본인의 데이터만 볼 수 있는가?
- [O] 데이터 정확성: 어떤 값을 어디서 가져오는가? (주문 시점 값 vs 현재 값)
- [O] 경계 · 오류: 0건, 마지막 페이지, 범위를 벗어난 페이지, 삭제된 상품은?
- [O] 정렬 · 페이지 계산이 계약과 같은가?
- [O] 표시 규칙(대표 상품 등)이 계약과 같은가?

(위 체크 표시는 팀이 코드와 표를 직접 읽어 본 뒤에 직접 표시한다.)

| 4 | orderQuery.js : listOrders (페이지 계산) | 시작 위치를 `page * pageSize` 로 계산해 1쪽이 11번째 건부터 시작한다 (0부터 시작하는 계산) | 5장 규칙 4 (페이지는 1부터 시작) | 결함 4: 페이지는 1부터 시작한다 (12건 중 1쪽은 10건, 2쪽은 2건, 3쪽은 빈 목록) | `(page - 1) * pageSize` |

## PR 리뷰 코멘트 (에이전트에게 돌려보낸다고 가정하고 작성)
- **getOrderDetail — 권한 검사 누락 (필수 수정).** 현재 `userId` 를 쓰지 않아 다른 구매자의 주문번호만 알면 상품 · 배송지가 조회된다. 5장 규칙 1 에 따라 본인 주문이 아니면 없는 주문과 같은 `NOT_FOUND` 여야 한다. 재현: 결함 1 테스트.
- **getOrderDetail — 가격 출처 오류.** 상세 금액을 현재 상품 가격으로 다시 계산해서 가격 인상 뒤 과거 주문의 금액이 바뀐다. 5장 규칙 2 는 주문 시점의 값을 요구한다. 주문 항목에 저장된 `unitPrice` 를 써야 한다. 재현: 결함 2 테스트.
- **listOrders — 정렬 방향 반대.** 오래된 주문이 먼저 나온다. 규칙 3 은 최신순이며 같은 시각이면 주문번호가 큰 것이 먼저다. 재현: 결함 3 테스트.
- **listOrders — 페이지 시작 위치 오류.** `page * pageSize` 는 0 기반 계산이라 1쪽이 첫 10건을 건너뛴다. 규칙 4 의 1 기반 페이지에 맞게 `(page - 1) * pageSize` 여야 한다. 재현: 결함 4 테스트.
- **representativeName — 개수 표기 오류.** "외 N건" 은 나머지 종류 수여야 하는데 전체 종류 수를 쓴다. `items.length - 1` 로 고쳐야 한다. 재현: 결함 5 테스트.
